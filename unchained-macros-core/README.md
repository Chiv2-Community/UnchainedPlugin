# unchained-macros-core

Backend-independent native methods, detours, listeners, patches, and selection filters.
No memory scanner, reflection engine, resolver-kind enum, or startup-phase policy.

`runtime_bindings` documents outer native declarations and expands annotated
impls. Method documentation belongs to `bind_resolved_func`, including bindings
generated by the Kismet backend. Unbound helpers retain only their authored docs
and unchanged Rust bodies.
Helper-only impls need no attribute; if annotated, they pass through unchanged.
Binding signature metadata shares its declaration's impl. Generated code uses
core's hidden dependency re-exports, not consumer `inventory` or `retour` paths.

Implement `AddressResolver` with an associated `Context`. A `Resolver<R>` holds
the implementation, stable name, and optional selector filter.
`ResolverDeclaration` associates generated declarations with their backend type.
`bind_resolved_func(Key)` uses that declaration, preserving provider keys and
selection. `bind_resolved_func(Backend, &DESCRIPTOR)` instead accepts a typed
`Resolver<Backend>` static without a marker type. The backend registers that
resolver for discovery; both forms share native calls, signature metadata, and hooks.

- `FunctionBinding<R>` references `Resolver<R>` and stores the native target name.
- `NativeTarget<F, E, X, R>` holds one typed callback slot for the function.
- `DetourRegistration<T>` pairs a `SupportsDetour` target with its exact replacement type and owns callback initialization.
- `ListenerRegistration` references the actual callback slot and owns initialization.
- `PatchRegistration<R>` references its resolver and names the patch factory/static.

Discover typed registrations:

```rust,ignore
resolver_inventory_for::<Backend>()
binding_inventory_for::<Backend>()
detour_inventory_for::<Backend>()
listener_inventory_for::<Backend>()
patch_inventory_for::<Backend>()
```

Function inventory stores direct `&FunctionBinding<R>` trait-object references.
Typed discovery downcasts the accessor's exact storage, without registration
wrappers. Required-value inventory stores direct `&ValueBinding` references.
Detour discovery erases the callback type to `&dyn DetourInfo`. Both detour and
listener discovery filter by the target resolver’s backend. Neither resolves an
address or evaluates a condition.
Selection and required patch coverage do not combine unrelated backend types.
Patch IDs remain globally unique.

## Initialization

The host chooses when each backend's context is valid:

```rust,ignore
unsafe {
    initialize_bindings_for::<Backend>(&context, &selectors)?;
    apply_patches_for::<Backend, _>(&context, &selectors, &mut writer, &mut patch_state)?;
}
for hook in detour_inventory_for::<Backend>() {
    if hook.resolver().supports(&selectors) && !hook.initialized() {
        unsafe { hook.attach(true)?; }
    }
}
```

Keep native callers quiescent during publication and attachment. A retained
`PatchState` prevents completed patches from running again during retries.
Backends decide whether/how to cache successful resolution; core publishes native
bindings once and rejects rebinding.

Address claims and trampoline publication are **global across backends**.
Already-bound aliases receive a newly attached trampoline; aliases bound later
inherit it during initialization. With the required quiescent callers,
original-call bypass does not depend on backend discovery order.
Attachment selects the entry, exit, or replacement wrapper and publishes the
original trampoline to aliases. The target remains claimed while passive.
Auto-activation off skips callback conditions, not trampoline publication.

`function_is_bound_for::<Backend>(name)` and
`selectors.supports_resolver_for::<Backend>(name)` scope name queries to a backend.

## Function listeners

```rust,ignore
#[bind_func_entry_listener(Native::Call, || diagnostics_enabled())]
unsafe fn entered(value: &u32, output: &*mut u32) {}

#[bind_func_exit_listener(Native::OtherCall)]
unsafe fn returned(result: &bool) {}
```

- One callback per method: entry, exit, or detour.
  Call `validate_callback_registrations_for::<Backend>(&selectors)` before any
  attachment. It checks each selected callback's target identity,
  including passive registrations, without evaluating conditions.
- Entry listeners borrow the live inputs, then the wrapper calls the original once.
  Pointer inputs are borrowed addresses. Exit listeners run after the original
  returns and borrow its result only (`&()` for void). Neither wrapper retains inputs.
- Direct project calls through the native binding bypass **all** callbacks.
  Native, callback-induced, and condition-induced recursion is observed normally.
  No recursion guard or depth limit is provided. Callback authors must terminate
  recursive paths; unbounded reentry can overflow the stack.
- Observer/condition panics are caught; original execution continues. No exit is promised for exceptions,
  aborts, panicking detours, or other paths that do not return normally.
- Conditions and feature gates control activation.
  Conditions are attachment-time gates, evaluated once when auto-activation is
  enabled and never by dispatch/status queries. Auto-activation off skips them.
  Condition-induced native calls invoke enabled observers normally.
  Slot/registration `set_enabled` changes logical activation without reevaluation.
  `DetourInfo::enabled` / `set_enabled` refer to the detour callback only.
  `DetourInfo::detour` exposes the physical hook for inspection.
- Addresses remain globally owned across backends. A second independently
  described alias cannot attach another dispatcher; late aliases still share
  the trampoline for original-call bypass.

Unsafe callbacks must not mutate observations, retain temporary borrows, release
engine-owned storage, or invalidate borrowed arguments/results. Raw pointers,
interior mutability, and arbitrary unsafe Rust cannot be sandboxed.

### Backend-specific listener targets

Callback attributes use the method’s `__UNCHAINED_TARGET_Method` reference. A
`CallbackTarget` supplies its resolver and physical attachment.
Implement only the supported capabilities:

- `SupportsDetour`: read the replacement and inspect the physical hook.
- `SupportsEntry`: dispatch with `observe_entry`.
- `SupportsExit`: dispatch with `observe_exit` on the returned value.

Both native backends generate `NativeTarget<F, E, X, R>`: `F` is the native ABI,
`E` is `unsafe fn(&Input, ...)`, and `X` is `unsafe fn(&Result)`. Kismet’s `DummyExecTarget`
implements only entry. It has no callable native body, replacement, or exit slot.

### Handwritten registrations

```rust,ignore
use unchained_macros_core::{DetourInfo, DetourRegistration, NativeTarget};

type Call = unsafe extern "C" fn(usize) -> usize;
type Target = NativeTarget<Call, unsafe fn(&usize), unsafe fn(&usize), Backend>;
static TARGET: Target = unsafe { Target::new(&BINDING, replace, enter, exit, |f| f as *const ()) };
static REPLACEMENT: DetourRegistration<Target> =
    DetourRegistration::new("replacement", &TARGET, replacement, condition);
// Optional discovery; direct attachment doesn't consult inventory.
inventory::submit! { &REPLACEMENT as &dyn DetourInfo }
```

During quiescent startup, `unsafe { REPLACEMENT.attach(true)? }` attaches the
replacement wrapper and publishes the typed callback. A failed or duplicate owner
cannot toggle another registration’s callback. `set_enabled` controls only the
logical replacement. Generated registrations use the same lifecycle.

For a listener, use `ListenerRegistration::new(name, &ListenerAction::entry(&TARGET, entered), condition)`
or `ListenerRegistration::new(name, &ListenerAction::exit(&TARGET, returned), condition)`.
See [`tests/manual_api.rs`](tests/manual_api.rs) for complete handwritten
binding submission, dispatch, conflicting registrations, toggles, late aliases,
and original-call bypass.

Low-level slot `register` is unsafe: it bypasses descriptor result-signature and
attachment checks. Prefer descriptor registration. Slot reads/status/activation
remain safe; backend fixtures using direct publication must uphold its full ABI,
ownership, and condition-evaluation contract.

Backend argument marshalling, result semantics, coverage, and unsupported shapes
remain backend responsibilities. Core never treats a wrapper address as a native ABI.

## Native globals

Use `bind_resolved_value(Resolver, Address)` for inline storage, or `Value` for a
pointer slot. Static bindings expose `NativeGlobal<T>::read()` returning a raw
pointer. Read explicitly at each use; dispatch methods through rust-ctables or
the native type's ordinary methods. No target opt-in or generated forwarding is needed.
Initialize registered values with `initialize_value_bindings_where`, filtered by the frozen snapshot.
Keep native spelling, synchronization, and declaring-header placement; never
cache the pointee of a replaceable slot.
